2. Implementation Architectures

The same government rules can be built using different logical structures. Compare how these code patterns organize the decision flow.

Simple IF Structure

Linear execution. Each rule checks independently. Final rules (like the 12-month ban) must overwrite previous results.

if income < 800:
  status = "Full"
if income <= 1600...:
  status = "Partial"
if prior_grant <= 12:
  status = "Declined"

If-Else-If Ladder

Efficient and hierarchical. The first matching condition wins. Prioritizes the disqualification rule at the top.

if prior_grant <= 12:
  return "Declined"
elif income < 800:
  return "Full"
elif partial_rules:
  return "Partial"

Nested IFs

Filters by group. First checks the "Gatekeeper" rule (Recency), then nests sub-logic for amount levels inside.

if no_prior_grant:
  if income < 800:
    status = "Full"
  else:
    check_partial_logic()
else:
  status = "Declined"

4. Socio-Economic Impact Analysis

The "1-Sol" Benefit Cliff

Our data visualization shows a sharp drop in support at exactly 800 soles. A household earning 799 qualifies for full aid, while earning just 1 sol more strips away that status entirely. This binary threshold creates a poverty trap where small economic improvements lead to net losses in household security.

Recency vs. Severity

The logic prioritizes "Grant Recency" over "Crisis Severity." As seen in Household 3, even families in extreme drought with low water access scores are rejected if they received aid within the last year, ignoring the cumulative impact of ongoing disasters.
